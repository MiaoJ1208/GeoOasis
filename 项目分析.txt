一、项目总体定位

本项目是一个基于 Cesium、Vue 3、Vite、Pinia、Yjs、IndexedDB、Hocuspocus 和 WebSocket 的公路交通数字孪生原型系统。系统将三维地形地貌、公路基础设施模型、道路网络、车辆轨迹、视频识别事件、交通态势预测结果和空间分析工具集成在同一个三维 WebGIS 场景中，服务于公路运行监测、交通状态展示、数据映射和后续业务扩展。

从甲方使用角度看，系统提供的主要业务流程是：
1. 打开三维数字孪生场景。
2. 加载道路网络、地形影像、公路设施模型和业务数据。
3. 查看车辆轨迹、视频识别车辆映射、交通态势预测播放结果。
4. 通过右侧业务按钮触发融合解析程序。
5. 通过图层面板、属性面板、坐标定位和空间分析工具完成辅助查看与维护。

从维护开发角度看，项目主要由以下几部分组成：
1. GeoOasis 前端可视化主系统，位于 GeoOasis/src。
2. GeoOasis 轻量后端，位于 GeoOasis/src/backend，用于 /run-merge 接口和协同编辑 WebSocket 服务。
3. 静态数据和模型资源，位于 GeoOasis/public。
4. Fusion-Analysis 视频识别与融合分析程序，位于 Fusion-Analysis，用于 YOLOv11 车辆检测、过线统计和 WebSocket 事件推送。

二、项目已经实现的主要功能

1. 三维地图与数字孪生场景

系统使用 Cesium Viewer 创建三维地球场景，支持影像底图、地形、三维模型、道路线、车辆实体、轨迹路径和业务图层叠加显示。

主要能力包括：
1. 创建三维 WebGIS 场景。
2. 加载 Cesium World Terrain 等地形。
3. 切换 Bing、ArcGIS、本地 NaturalEarthII 等底图。
4. 开启地表半透明和地下观察，便于观察隧道、地下工程或被地表遮挡的对象。
5. 支持 Home 回到初始视角、经纬度高度输入定位。
6. 支持点、线、面、矩形、模型、图片等空间对象的绘制和显示。

核心代码位置：
1. GeoOasis/src/components/Editor.vue：Cesium 容器组件。
2. GeoOasis/src/composables/useSetup.ts：Viewer 初始化、地表半透明、鼠标交互、CesiumGizmo 初始化。
3. GeoOasis/src/editor/editor.ts：Editor 内核，连接 Cesium Viewer、Yjs 文档和场景实体。
4. GeoOasis/src/editor/terrain.ts：地形选项和地形切换。
5. GeoOasis/src/editor/imageryLayerManager.ts：底图和影像图层管理。
6. GeoOasis/src/layer/utils.ts：根据图层 provider 创建 Cesium imagery/data provider。

2. 道路网络加载与展示

甲方点击“加载道路数据”后，系统读取 GeoOasis/public/data/roadCity.json，将其中的道路 LineString 数据转为 Cesium polyline 实体并贴地显示。

核心代码位置：
1. GeoOasis/src/components/DataPanel.vue：业务按钮，点击后触发 load-road 事件。
2. GeoOasis/src/App.vue：接收 load-road 事件，调用 roadVisualRef.value?.loadRoadData()。
3. GeoOasis/src/components/RoadVisual.vue：loadRoadData、loadGeoJSON 负责读取 roadCity.json 并创建道路实体。
4. GeoOasis/public/data/roadCity.json：道路基础线数据。

实现逻辑：
1. DataPanel 发出 load-road。
2. App.vue 的 onLoadRoad 调用 RoadVisual 暴露出来的 loadRoadData。
3. loadRoadData 获取 editor.viewer。
4. loadGeoJSON fetch 指定数据文件。
5. 遍历 data.geometries 中的 LineString。
6. 使用 Cesium.Cartesian3.fromDegrees 将经纬度转换为 Cesium 世界坐标。
7. 使用 viewer.entities.add 添加 polyline，并保存到 roadEntities 数组中，便于后续清理或维护。

3. 交通态势预测结果动态播放

论文中交通流预测部分提出基于改进 T-GCN 的交通流预测方法，并将预测结果转为多级交通运行状态。当前仓库中没有发现 T-GCN 训练或推理源码；GeoOasis 当前实现的是“预测结果/交通等级结果的三维动态可视化播放”。也就是说，模型预测结果已经以 GeoJSON 数据形式放入 public/data，前端负责读取、按时间戳播放和按等级着色。

核心代码位置：
1. GeoOasis/src/components/DataPanel.vue：点击“交通态势预测”触发 toggle-traffic-analysis。
2. GeoOasis/src/App.vue：toggleTrafficAnalysis 切换 store.isTrafficAnalysis。
3. GeoOasis/src/store/GeoOasis.store.ts：保存 isTrafficAnalysis 状态。
4. GeoOasis/src/components/RoadVisual.vue：loadTrafficData、updateTrafficDisplay、startTrafficAnimation、pauseTrafficAnimation、resumeTrafficAnimation、stopTrafficAnimation、handleTimelineChange。
5. GeoOasis/public/data/road_network_with_level.geojson：当前实际读取的交通状态等级数据。
6. GeoOasis/public/data/road_network_with_speeds.geojson：项目中存在的速度数据文件，但 RoadVisual.vue 当前默认使用 with_level 文件。

实现逻辑：
1. 用户点击“交通态势预测”按钮。
2. App.vue 切换 store.isTrafficAnalysis。
3. RoadVisual.vue watch isTrafficAnalysis。
4. 开启时调用 loadTrafficData，读取 /data/road_network_with_level.geojson。
5. 遍历 features，读取 feature.properties.Id、feature.geometry.coordinates、feature.properties.traffic_level。
6. traffic_level 是“时间戳 -> 交通等级”的对象；系统合并所有路段的时间戳并排序，形成 trafficTimestamps。
7. updateTrafficDisplay 根据当前时间戳读取每条路的等级，调用 getTrafficLevelColor 映射颜色。
8. 每个时间步先移除上一帧 trafficEntities，再为当前时间戳创建新的 polyline 实体。
9. startTrafficAnimation 使用 setInterval，默认每 1000ms 推进一个时间戳。
10. 页面底部 traffic-timeline-control 显示播放按钮、进度条、当前时间戳和百分比。
11. 用户拖动进度条时，handleTimelineChange 根据 0-100 的进度值换算时间戳索引，并暂停自动播放。

交通等级颜色逻辑：
1. 1：绿色，畅通。
2. 2：青色，基本畅通。
3. 3：黄色，轻度拥堵。
4. 4：橙色，中度拥堵。
5. 5：红色，严重拥堵。
6. 未知等级：灰色。

4. 车辆历史轨迹映射

系统支持将车辆轨迹数据映射到 Cesium 场景中，以车辆模型、尾迹路径和车牌标签表达车辆运动过程。

核心代码位置：
1. GeoOasis/src/components/DataPanel.vue：点击“轨迹数据映射”触发 load-car-trajectories。
2. GeoOasis/src/App.vue：handleLoadRoad 调用 RoadVisual.loadTrajectories。
3. GeoOasis/src/components/RoadVisual.vue：loadTrajectories。
4. GeoOasis/src/editor/assetLibrary.ts：模型资源库，提供车辆模型 URL。
5. GeoOasis/public/data/20251030_163823_170604/Simulatedtrajectory1.json：当前默认轨迹数据。
6. GeoOasis/public/SUV_gltf/*：默认 SUV 模型资源。

实现逻辑：
1. App.vue 调用 loadTrajectories("/data/20251030_163823_170604/Simulatedtrajectory1.json", 2)。
2. RoadVisual.vue fetch 轨迹数据。
3. 以 plateNo 作为车辆分组键。
4. 每条轨迹点读取 longitude、latitude、altitude、timeStamp.$numberLong 或 time。
5. 每辆车的轨迹点按时间排序。
6. 计算所有车辆的 globalStart 和 globalStop，用于设置 Cesium clock。
7. 从 assetLibrary 获取指定 index 的模型 URL。
8. 为每辆车创建 Cesium.SampledPositionProperty，并对每个时间点 addSample。
9. 使用 Cesium.VelocityOrientationProperty 根据运动方向计算朝向。
10. 使用 CallbackProperty 将 VelocityOrientationProperty 与一个 Z 轴 -90 度修正四元数相乘，修正 glTF 模型默认朝向。
11. viewer.entities.add 创建车辆实体，包含 position、orientation、model、path、label。
12. 设置 viewer.clock.startTime、stopTime、currentTime、multiplier 和 shouldAnimate，驱动车辆按时间运动。

5. 视频识别车辆实时映射

论文中视频数据映射部分提出：使用 YOLOv11 完成车辆检测，使用改进质心追踪进行车流量统计，再通过 WebSocket 将检测事件实时推送到三维数字孪生空间。当前项目中该能力由 Fusion-Analysis 负责检测和推送，GeoOasis 负责接收事件并在 Cesium 中生成虚拟车辆。

前端核心代码位置：
1. GeoOasis/src/components/DataPanel.vue：点击“视频数据映射”触发 load-video-vehicle。
2. GeoOasis/src/App.vue：videoVehicle 调用 RoadVisual.videoVehicle。
3. GeoOasis/src/components/RoadVisual.vue：videoVehicle、getVehicleWsUrl、initSocket、connectVehicleSocket、ROAD_LANES、spawnRealtimeVehicle。
4. GeoOasis/public/SUV_gltf/*：小车模型。
5. GeoOasis/public/truckModel.glb：卡车模型。

后端/识别核心代码位置：
1. Fusion-Analysis/app.py：YOLOv11 推理、多视频任务、过线统计、WebSocket 消息发送。
2. Fusion-Analysis/ws_server.py：WebSocket 广播服务，默认端口 8765。
3. Fusion-Analysis/src/tracker.py：目标跟踪工具类，包含检测框匹配、轨迹维护、插值和平滑。
4. Fusion-Analysis/MULTI_VIDEO_USAGE.md：多视频 WebSocket 消息格式说明。
5. Fusion-Analysis/system-start.bat：启动 Fusion-Analysis/app.py。

前端实现逻辑：
1. 用户点击“视频数据映射”。
2. App.vue 调用 RoadVisual.videoVehicle。
3. videoVehicle 获取 viewer、飞到预设视角，并调用 connectVehicleSocket。
4. getVehicleWsUrl 优先读取 VITE_VEHICLE_WS_URL；未配置时默认 ws://127.0.0.1:8765。
5. initSocket 创建 WebSocket 连接。
6. 收到消息后 JSON.parse。
7. 当前重点处理 msg.type === "line_cross" 的消息。
8. 使用 msg.video_id 找到 ROAD_LANES 中配置的虚拟车道起点和终点。
9. 使用 msg.payload.class 判断车辆类型；truck 使用卡车模型，其它默认为 car。
10. spawnRealtimeVehicle 创建一段从 now 到 stop 的 SampledPositionProperty，使车辆在 lifeSeconds 时间内从起点移动到终点。
11. 使用 VelocityOrientationProperty 计算朝向，并通过四元数修正模型方向。
12. 添加 Cesium model 实体，实现视频识别事件到三维道路空间的实时映射。

WebSocket 协议格式：

{
  "type": "line_cross",
  "video_id": "road_1",
  "payload": {
    "class": "car",
    "direction": "up",
    "count_up": 10,
    "count_down": 3,
    "class_line_counts": {
      "car": 5,
      "truck": 2
    }
  }
}

Fusion-Analysis 实现逻辑：
1. app.py 中 VideoDetectionTask 表示一个独立视频检测线程。
2. 每个任务持有 video_id、YOLO model、device、counting_line、confidence_threshold、iou_threshold、match_threshold 等配置。
3. run 方法读取视频帧，将帧转为 RGB，调用 self.model(frame_rgb, device=..., conf=..., iou=..., max_det=...) 执行 YOLOv11 推理。
4. 若配置了 counting_line，则调用 count_objects。
5. count_objects 遍历检测框，计算车辆中心点。
6. 对当前检测中心和历史轨迹做距离匹配，并使用简单速度预测 last + (last - prev) 辅助匹配。
7. 当车辆中心点连线与计数线相交时，按 y 方向变化判断 up/down，更新 count_up、count_down 和 class_line_counts。
8. 调用 push_line_event 组装 line_cross 消息并通过 ws_server.send 广播给前端。
9. ws_server.py 维护 WebSocket 客户端集合，send 方法把消息投入 asyncio 事件循环并广播给所有客户端。

1. Editor 构造函数创建 this.doc = new Y.Doc()。
2. 从 doc 中创建 title、options、ElementsMap、LayersMap、assetArray、YImageryLayers 等共享结构。
3. new IndexeddbPersistence("oasis-doc", this.doc) 将 Yjs 文档持久化到浏览器 IndexedDB。
4. UndoManager 绑定 elements、layers、baseLayers、assetLibrary.assetArray、imageryLayerManager.imageryLayers 等结构，实现统一撤销/恢复。
5. elements.observeDeep 和 layers.observeDeep 监听共享数据变化。
6. 当 Yjs 中元素新增、修改、删除时，editor.ts 同步增删改 Cesium Entity。
7. 当 Yjs 中图层新增、删除时，editor.ts 同步增删 Cesium DataSource、ImageryLayer 或 3DTiles primitive。
8. changeRoom(roomId) 会先断开旧 provider，再通过 createHocuspocusProvider(Hocuspocus_URL, roomId, doc) 接入指定协同房间。
9. HocuspocusProvider 负责把本地 Y.Doc 与 ws://localhost:3001 的 Hocuspocus 服务同步。
10. useSync 将 Yjs Map/Array 转为 Vue ref/computed 数据，供 LayersBar、InfoPanel 等组件渲染。

2. 隧道/地下空间半透明效果

论文对应内容：
提出基于相机与参考点距离的地表透明度动态调节方法，用于解决地下工程难以观测的问题。

项目实现位置：
1. GeoOasis/src/composables/useSetup.ts：当前实际启用地表半透明和动态透明度调节。
2. GeoOasis/src/editor/tunnelClipping.ts：提供隧道裁剪平面集合辅助函数，但当前主流程中未看到被调用。

useSetup.ts 中的实现逻辑：
1. cesiumViewer.scene.globe.translucency.enabled = true，开启地表半透明能力。
2. cesiumViewer.scene.screenSpaceCameraController.enableCollisionDetection = false，允许相机进入地下。
3. cesiumViewer.scene.globe.depthTestAgainstTerrain = true，开启地形深度测试。
4. 使用 Cartesian3.fromDegrees 设置参考点 referencePoint。
5. 在 updateGlobeTranslucency 中读取 camera.position。
6. 使用 Cartesian3.distance 计算相机到参考点距离。
7. 当距离小于 thresholdDistance 1000 米时，frontFaceAlpha 设置为 0.5。
8. 当距离大于阈值时，frontFaceAlpha 恢复为 1。
9. 通过 cesiumViewer.scene.camera.changed.addEventListener(updateGlobeTranslucency) 监听相机变化，实时更新透明度。

tunnelClipping.ts 中的实现逻辑：
1. createTunnelClippingPlanes(center, options) 接收中心点、宽度、高度、enabled。
2. 创建 6 个 ClippingPlane，分别对应东西南北上下方向。
3. unionClippingRegions: true 表示多个裁剪区域取并集。
4. modelMatrix 使用 Transforms.eastNorthUpToFixedFrame(center)，使裁剪盒以中心点局部 ENU 坐标系定位。
5. 返回 ClippingPlaneCollection，可供后续挂到 globe、tileset 或 model 上使用。

维护建议：
如果甲方需要更精确的隧道开挖窗口或局部裁剪，应在 Viewer 初始化或具体地下模型加载后调用 createTunnelClippingPlanes，并明确挂载对象；当前可见效果主要来自地表透明度，而不是裁剪平面。

3. 交通设施编辑控件与屏幕自适应尺度保持

论文对应内容：
引入面向交通设施编辑的操作控件与屏幕自适应尺度保持方法，提高场景构建过程中的操作精度。

项目实现位置：
1. GeoOasis/src/composables/useSetup.ts：CesiumGizmo 初始化和拖拽结果写回。
2. GeoOasis/src/thirdParty/cesium-gizmo/*：三维编辑控件实现。
3. GeoOasis/src/editor/type.ts：DrawMode、GizmoMode 类型。
4. GeoOasis/src/components/ToolsBar.vue：绘制模式、gizmo 模式和模型选择 UI。

实现逻辑：
1. useSetup.addPointerListener 创建 CesiumGizmo(viewer, options)。
2. drawMode 为 SPACE 时显示 gizmo，否则隐藏。
3. gizmoMode 变化时同步到 gizmo.mode。
4. onDragMoving 回调返回 mode 和 result。
5. TRANSLATE 模式将 result.x/y/z 写入元素 positions。
6. ROTATE 模式将 heading/pitch/roll 写入元素 orientation。
7. UNIFORM_SCALE 模式将 result[0]/[1]/[2] 写入元素 scale。
8. 数据写回 editor.mutateElement 后进入 Yjs，随后由 Editor 同步到 Cesium Entity。

4. 系统编辑记录、本地缓存和撤销恢复

论文对应内容：
结合 Yjs 框架与 IndexedDB 数据库，设计轻量级三维场景编辑状态持久化机制，实现编辑操作的本地缓存与恢复。

项目实现位置：
1. GeoOasis/src/editor/editor.ts。
2. GeoOasis/src/composables/useYjs.ts。
3. GeoOasis/src/composables/useSync.ts。
4. GeoOasis/src/store/GeoOasis.store.ts。

实现逻辑：
1. Editor 构造函数创建 Y.Doc。
2. 各类业务数据都存入 Yjs 共享结构：
   title -> Y.Text
   options -> Y.Map
   ElementsMap -> Y.Map
   LayersMap -> Y.Map
   baseLayers -> Y.Map
   assetArray -> Y.Array
   YImageryLayers -> Y.Array/Y.Map
3. IndexeddbPersistence("oasis-doc", this.doc) 把 Y.Doc 自动持久化到浏览器 IndexedDB。
4. 用户新增、删除、修改元素和图层，本质上都是修改 Yjs 结构。
5. Y.UndoManager 绑定主要共享结构，记录编辑事务。
6. useYjs.ts 调用 editor.undoManager.undo() 和 redo() 实现撤销/恢复。
7. 下次打开页面时，IndexedDB 中的 oasis-doc 会恢复上次编辑状态。

5. 协同通信协议

系统需要数据交互层支撑实时同步和多端共享。项目中协同编辑使用 Yjs + Hocuspocus；视频事件使用普通 WebSocket；融合解析使用 HTTP POST。

视频事件协议：
1. Fusion-Analysis/ws_server.py 默认提供 ws://127.0.0.1:8765。
2. GeoOasis/src/components/RoadVisual.vue 的 getVehicleWsUrl 默认连接 ws://127.0.0.1:8765，也可用 VITE_VEHICLE_WS_URL 配置。
3. 重点处理 type=line_cross 消息。
4. video_id 用于匹配 ROAD_LANES 中的路段。
5. payload.class 用于决定 car/truck 模型。

融合解析 HTTP 协议：
1. 前端 POST /run-merge。
2. Vite 代理到 http://localhost:3000。
3. Express 后端启动 bat。

6. YOLOv11 车辆检测与改进质心追踪

论文对应内容：
基于 YOLOv11 实现车辆目标检测，设计改进质心追踪算法完成车流量统计。

项目实现位置：

app.py 中的实现逻辑：

八、当前维护注意点

1. 项目报告旧文件和部分源码注释存在乱码

本报告已重新以正常中文内容替换项目分析.txt。若界面或源码注释仍显示乱码，建议统一按 UTF-8 重新保存相关文件。

2. contants.ts 文件名拼写

当前文件名是 GeoOasis/src/contants.ts，不是 constants.ts。多个文件已经按 contants.ts 引用。若改名，需要同步修改所有 import。

3. Cesium Ion token 暴露在前端

当前 token 写在 src/contants.ts，构建后会暴露在前端资源中。正式交付时建议使用受限 token，并在 Cesium Ion 控制台限制域名和权限。

4. RoadVisual.vue 职责较重

RoadVisual.vue 同时负责道路加载、交通态势、轨迹、视频 WebSocket、车辆生成和时间线 UI。后续功能继续增加时，建议拆成：
1. useRoadNetworkLayer。
2. useTrafficTimeline。
3. useTrajectoryLayer。
4. useVideoVehicleMapping。

5. 交通态势每帧重建实体

当前 updateTrafficDisplay 每个时间步会删除并重建所有交通路段 polyline。该逻辑简单清晰，但路网变大时可能有性能压力。后续可改为初始化一次实体，播放时只更新 material。

6. T-GCN 模型代码未纳入当前仓库

当前仓库没有发现论文中改进 T-GCN 的训练和推理代码。GeoOasis 实现的是预测结果可视化。如果甲方要求完整预测闭环，需要补充算法服务和数据处理流程。

7. 视频映射空间精度是路段级映射

当前视频事件通过 video_id 映射到 ROAD_LANES 中的预设起终点，属于路段级或车道级表达，不是基于摄像机标定的真实图像坐标到地理坐标精确映射。若要提高精度，需要增加摄像头标定和图像坐标到地理坐标转换。

九、甲方简要使用路径

1. 启动系统：执行 pnpm dev 或 pnpm dev:all。
2. 打开前端页面后，使用左侧图层栏选择底图和地形。
3. 点击右侧“加载道路数据”，显示路网。
4. 点击“交通态势预测”，底部出现时间线，可播放或拖动查看不同时间的拥堵状态。
5. 点击“轨迹数据映射”，显示车辆按历史轨迹运动。
6. 点击“视频数据映射”，连接 Fusion-Analysis 的 WebSocket，将识别到的过线车辆映射到三维道路。
7. 点击“融合解析”，启动本地 Fusion-Analysis 程序。
8. 使用左侧图层栏管理图层和元素。
9. 选中元素后，在右侧属性面板修改属性。
10. 输入经纬度和高度，可快速定位到指定区域。

十、总结

GeoOasis 已形成一个可演示、可维护、可扩展的公路交通数字孪生系统原型。它的核心价值在于将 Cesium 三维场景、道路网络、交通态势预测结果、车辆轨迹、视频识别事件、空间分析工具和协同编辑机制统一到一个浏览器端三维 WebGIS 平台中。

当前项目已经较好覆盖论文中的系统集成和关键技术展示：Cesium 三维场景构建、地表半透明/地下观察、模型编辑、Yjs+IndexedDB 编辑记录、WebSocket 视频事件映射、交通态势时空播放等。后续如需面向生产环境交付，建议优先完善 T-GCN 预测服务闭环、视频空间精确标定、RoadVisual 模块拆分、大路网性能优化、正式 token 管理和中文编码统一。
